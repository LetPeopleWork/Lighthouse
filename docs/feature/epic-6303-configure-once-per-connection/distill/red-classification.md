behaviour (a missing member, a 200 where a refusal belongs, nothing read, no entry logged). BROKEN = it fails before
the assertion for a reason of its own (fixture, seeding, compile, an exception in the harness). Active guards pass
today and must keep passing.

**What the revision changed, and how it classified.**
- Validate goes through `POST /api/latest/worktrackingsystemconnections/validate`, the route the Validate button
  posts to; the Slice03 Validate scenarios are RED on the HTTP answer (400 where 200 belongs, a refusal without the
  relation types listed). The field-exists guard stays green over HTTP.
- What a Feature waits on and where an item hangs are read through `GET /api/latest/features/references` and
  `GET /api/latest/teams/{id}/metrics/wip`; Refresh History through `GET /api/latest/systeminfo/refreshlog`. The
  Portfolio's settings change through `GET …/portfolios/{id}/settings` and `PUT …/portfolios/{id}`. Every guard that
  uses them stays green.
- The recorded Azure DevOps organisation now names its hierarchy relation "Parent", as Azure DevOps does, so the
  native-parent scenario passes its "the native parent stands" half today and is RED on the missing finding — before,
  it failed on the parent, which no implementation would have fixed.
- New RED cases: AC-3.10 for the Size Estimate, Feature Owner and Estimation fields (3), AC-9.3 and AC-10.3 (an empty
  value behaves as today), and on the frontend the loading look and the late answer for a connection already left.
- The could-not-load scenario on the connection page is no longer a guard: it waits for the approved copy
  "Could not load this connection." and a Try again button, which the page does not have yet, so it is RED. As a guard
  it passed because the page shows no section at all today.
- Slice 05a has no save dialog: its dialog scenario became "saves without asking anything" (RED, the defaults are not
  sent yet; retired by slice 06). The dialog scenarios moved to slice 06 with the approved UI-3 copy.
