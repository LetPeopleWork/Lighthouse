## Shared records

### Decisions

#### D1

```text
Absent field: PortfolioSettingDto.InfersDefaultFeatureSize is bool? (the IgnoreDependencies precedent) and PortfolioExtensions keeps the stored value when it is absent, so an older UI, script or CLI payload cannot switch it off. A new Portfolio holds true. The column is additive: NOT NULL with default true for existing rows, generated by Create-Migration.ps1 for Sqlite and Postgres. The wire name is infersDefaultFeatureSize. Rejected: JsonRequired (turns every older payload into a 400), plain bool (missing field would mean false, which silently turns sizing off).
```
Governed slices: S1

#### D2

```text
Feature read model: Feature gains a derived read-only property HasNoChildWorkItemsYet (not Done, no child Work Items, not using the default size), exposed on FeatureDto and FeatureListRowDto and decoded by the frontend Feature model. It is true exactly when the switch is off for a childless Feature, so the note cannot claim a cause that is false and the frontend holds no copy of the rule. This replaces the DISCUSS expectation that the Feature payload gains nothing. Rejected: deriving it in the frontend from total work (a second copy of the rule that mislabels a Feature not yet refreshed), reading the Portfolio setting in the lists (the Team list and the timeline hold no Portfolio setting, and a Feature may sit in several Portfolios).
```
Governed slices: S3

#### D3

```text
Team page: a Team list holds the Features that a Team carries work for (FeatureRepository.FeaturesOfTeam). With the switch off a childless Feature has no Team work, so it is not listed on any Team page; that satisfies the rule that no Team carries remaining work for it. The note appears wherever the Feature is listed: the Portfolio Feature list and the Delivery timeline. The Team list uses the same warnings column and shows the note for a listed Feature that has no children, which cannot occur; no extra code. Flagged to the host: the product wording lists the Team page as a place of the note.
```
Governed slices: S3

#### D4

```text
Owner: Portfolio owns the sizing rule. It gains one setting, InfersDefaultFeatureSize (bool, true by default), and its two existing selectors GetFeaturesToExtrapolate and GetFeaturesToOverrideWithDefaultSize return no Feature when the setting is off. WorkItemService.UpdateRemainingWorkForPortfolio is unchanged: with both selections empty it neither clears real children nor extrapolates, so a childless not-Done Feature keeps no FeatureWork and IsUsingDefaultFeatureSize stays false (size 0). The percentile and estimate-field helpers are then never reached. Rejected: a branch in WorkItemService (transaction script over Portfolio data), a second sizing strategy object (one boolean, no second implementation).
```
Governed slices: S1, S2, S3

#### D5

```text
Propagation (changes the proposed domain event): no new event and no inline call. Remaining work is recomputed from stored data in every Portfolio and Team refresh cycle (WorkItemService.UpdateFeaturesForPortfolio and UpdateWorkItemsForTeam), exactly as it is for Default Feature Size today; Forecasting already reacts to PortfolioFeaturesRefreshed. A settings save therefore takes effect on the next refresh cycle, not at the click. The setting is classified Cost.Nothing in FetchShapingPropertyGuardTest: it shapes no fetch. Rejected: a PortfolioSettingsChanged event that forces recalculation (new edge and handler for a rule the cycle already re-evaluates; the existing sizing settings have no such event).
```
Governed slices: S1, S2, S3

#### D6

```text
Context map (ADR-270): the setting is Portfolio configuration, owned by Organisation set-up with the other connection-default style sizing settings; the rule is applied inside Work Items (WorkItemService refresh over Portfolio.Features); Forecasting is unchanged and reads the resulting size through the existing Feature refresh event. No new context and no new edge. One new glossary term, default Feature sizing (the on/off switch for inferring a size, distinct from default Feature size, the number); the term is recorded in the ADR-270 glossary and ARCHITECTURE.md section 4 by slice S1. UI surface (ADR-271): the Advanced tab of the Portfolio settings, inside the existing Default Feature Size group; the note surfaces on existing Feature lists and the Delivery timeline.
```
Governed slices: S1, S2, S3

#### D7

```text
Loading and failure looks (answers the open DESIGN item), each reusing what exists: Portfolio advanced settings keeps the existing settings-page gate (EditPortfolio gate.isLoading and its failure path); the new Switch renders from the loaded settings and so has no look of its own. Feature lists on the Portfolio and Team pages keep FeatureListDataGrid status from useFeatureList (keyed query; dimmed under a spinner, lone spinner, could-not-load message); only a tooltip sentence changes. Delivery timeline keeps its existing load and failure handling; only the bar note text changes. Delivery Feature-size chart is unchanged: it reads the recorded IsUsingDefaultSize flag, so it needs no new state. No view shows a previous answer as current: the sentence derives from the same row that is on screen.
```
Governed slices: S1, S2, S3

#### D8

```text
Formal verification mapping: the sizing rule is a finite pure total function of switch, Done, child count, override membership and estimate. Checker: Quint 0.33.1 (state model, run and bounded verify with behavioral mutants), because the claims are safety and exclusion only. Agda is not needed (no proof beyond the finite domain). TLA+/TLC is not needed (no temporal or fairness claim; see liveness closure). Property-based testing: not applied, because the domain is finite and fully covered by native table-style example cases (closed-world falsifier gate). Types: native bool plus a guarded selector; the invalid combination off-and-using-default is made unrepresentable by the selectors returning no Feature, and is not enforced by the type system (C# runtime checker only).
```
Governed slices: S1, S2, S3

#### D9

```text
Checklist items: RBAC unchanged (PortfolioWrite on the existing PUT, PortfolioRead on GET settings; the Switch sits behind the same useRbac gating). Lighthouse-Clients: updatePortfolio passes an untyped payload, no change; the absent-field rule keeps older client payloads safe. Website: one line at finalize, host-owned. No Epic. ### Constraints
```

#### K1

```text
Switch domain: boolean, no range. Existing Portfolios migrate to true; a new Portfolio (API and create wizard) holds true; an absent wire value keeps the stored value. Nullable on the wire only (deviation from the plain-bool Portfolio properties, deliberate).
```

#### K2

```text
Off affects only a not-Done Feature without child Work Items and the override-states rule: Done Features, Features with children and the percentile calculation are unaffected. Stored values of Default Feature Size, percentile option, history days, size-estimate field mapping and override states are never cleared by switching off.
```

#### K3

```text
Old records are not rewritten: Delivery metric history and archived Deliveries keep the IsUsingDefaultSize flag recorded; DeliveryMetricValuesProjector and Delivery.cs are unchanged.
```

#### K4

```text
Forecasts take size 0 with no special handling: no change to Forecasting, Delivery likelihood or the timeline beyond the note.
```

#### K5

```text
EF migrations are additive only, generated by Create-Migration.ps1 for all providers after a backend build; no dotnet ef migrations add. The HistoricalSchemaPatch test helper lists the new column.
```

#### K6

```text
Copy uses the configurable terms (Feature, Work Items, Portfolio) from the terminology hook; no Epic. A new backend scenario drives the application-service port IWorkItemService; a host starts only as a named skeleton or wire contract.
```

#### K7

```text
Test budgets: default per-test and property budgets and default CI share apply; no derogation requested. Test command cwd is the repository root.
```

#### K8

```text
Platform risk: none. One additive NOT NULL DEFAULT true column on Portfolios (expand-only), generated with Create-Migration.ps1 for every provider; no new service, config, port, secret or CI change.
```
