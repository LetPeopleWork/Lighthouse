# Slice 01 — DELIVER notes

## Step 01-01: the `Reports` table on both providers

**Generation.** A full `dotnet restore` + `dotnet build Lighthouse.sln` from `Lighthouse.Backend/`, then
`pwsh ./Create-Migration.ps1 -MigrationName AddReports` (Docker for the Postgres leg). `dotnet ef migrations add` was
never run directly. Afterwards: `dotnet build` of each migrations csproj with `--no-incremental`, then
`dotnet build Lighthouse.sln --no-incremental` (0 warnings, 0 errors).

| Provider | Migration | Snapshot |
|---|---|---|
| SQLite | `Lighthouse.Migrations.Sqlite/Migrations/20261013082234_AddReports.cs` (+ `.Designer.cs`) | `LighthouseAppContextModelSnapshot.cs` carries `Reports` |
| PostgreSQL | `Lighthouse.Migrations.Postgres/Migrations/20261013082248_AddReports.cs` (+ `.Designer.cs`) | `LighthouseAppContextModelSnapshot.cs` carries `Reports` |

**Emitted SQL**, read from the generated `CreateTable` and from
`dotnet ef migrations script AddSizingLogEntries AddReports` per provider:

SQLite

```sql

    "Id" INTEGER NOT NULL CONSTRAINT "PK_Reports" PRIMARY KEY AUTOINCREMENT,
    "TeamId" INTEGER NULL,

    "Name" TEXT NOT NULL,
```

PostgreSQL

```sql
CREATE TABLE "Reports" (
    "Id" integer GENERATED BY DEFAULT AS IDENTITY,
    "TeamId" integer,
    "PortfolioId" integer,
    "TemplateKey" character varying(64) NOT NULL,
    "Name" character varying(200) NOT NULL,
    "CreatedAt" timestamp with time zone NOT NULL,
    "ShownMetricKeysJson" text NOT NULL,
    "TemplatePayloadJson" text NOT NULL,
    "PayloadSchemaVersion" integer NOT NULL,
    "ConcurrencyToken" uuid NOT NULL,
    CONSTRAINT "PK_Reports" PRIMARY KEY ("Id"),
    CONSTRAINT "CK_Reports_ExactlyOneOwner" CHECK (("TeamId" IS NOT NULL AND "PortfolioId" IS NULL) OR ("TeamId" IS NULL AND "PortfolioId" IS NOT NULL)),
    CONSTRAINT "FK_Reports_Portfolios_PortfolioId" FOREIGN KEY ("PortfolioId") REFERENCES "Portfolios" ("Id") ON DELETE CASCADE,
    CONSTRAINT "FK_Reports_Teams_TeamId" FOREIGN KEY ("TeamId") REFERENCES "Teams" ("Id") ON DELETE CASCADE
);
CREATE INDEX "IX_Reports_PortfolioId" ON "Reports" ("PortfolioId");
CREATE INDEX "IX_Reports_TeamId" ON "Reports" ("TeamId");
```

**CHECK fallback: not needed.** Both providers emit the exactly-one-owner CHECK inline in `CREATE TABLE`, so no
provider relies on the factory alone. The factory still enforces it when it lands with the create path.

**Database-level proof.** `Lighthouse.Backend.Tests/Data/ReportsTableConstraintsTest.cs` builds its schema from the
real SQLite migrations (`Database.Migrate()`, foreign keys on), writes the rule-breaking rows as raw SQL so EF cannot
stop them first, and asserts: no owner is refused (`CHECK constraint failed`), two owners are refused, and deleting the
Team (a database-side `DELETE`) removes its report.

**Other checks.**
- `ExpandOnlyMigrationGuardTest`: green (4/4), including `RealMigrations_AddedAfterBaseline_AreAdditiveOnly`.
- Throwaway SQLite start (`Database__Provider=sqlite`, a scratch file, Kestrel endpoints overridden off 5169):
  reached "Application started", applied `20261013082234_AddReports`, no `PendingModelChanges` in the log.
- `HistoricalSchemaPatch` fixtures (`BlockedRuleSetMigrationTests`, `DeliveryMetricSnapshotDayKeyMigrationTests`):
  green (13/13) with no new entry — `Reports` is a new table, not a column on `Teams`, `Portfolios` or `Deliveries`.

## Step 01-20: create timing against the 10-second budget

**Verdict: within budget by more than an order of magnitude. The fallback (one item load per owner per create) was
not applied.** Every create of a 365-day Then took 0.23–0.60 s server-side, at load averages from ~11 to ~30 on a
shared machine; opening the report took 0.11–0.26 s.

**Source: a seeded large Team, not the dev instance.** The local instance on :5169 was not running this slice-01
build (it belongs to another session and was seen restarting and stopping), so it could not answer for this code, and
it was not touched. The measurement comes from `ReportCreationTimingProbe`
(`Lighthouse.Backend.Tests/API/Integration/Reports/`), `[Explicit]`, so it never runs in the default or CI filters:
in the connector-excluded run, the Reports-filtered run and the `TestCategory=epic-5878-baseline` run it reports
`NotExecuted`.

**Team size.** 2 000 finished Work Items over 400 days (5 a day, Cycle Times 1–30 days), 150 in progress (started
4–120 days ago), on SQLite through the real ASP.NET host (`WebApplicationFactory`). Then's 85th percentile rested on
1 825 finished Work Items, so the full year was read. For comparison, the busiest real Team in the dev database
finished ~615 Work Items in a year.

**Request.** `POST /api/latest/teams/{id}/reports` with `thenAndNow { thenEndDate: today, thenLengthDays: 365,
nowLengthDays: 365 }`, then `GET /api/latest/teams/{id}/reports/{reportId}` once per reading. `ElapsedMs` is read off
the structured property of the "report created" Information line from `ReportCommands`; the POST is also timed from
the caller's side.
