Pivotal events, left to right: organisation set up → items fetched → unit data refreshed → forecasts updated → promise made, kept, missed or renegotiated → signal changed → report created. Licence expired gates them all. Domain events are the default way one context reacts to another.

Who owns which data

Source data comes from the trackers and has one owner. Every other context stores what it calculates in its own tables and points at items by ID only. Nobody writes another context's tables. Ownership is logical: one database, foreign keys and cascades stay.

      │ Forecasting       │  │ Flow metrics      │  │ Promises           │   Signals: signal history (target)
      │ forecasts         │  │ daily snapshots   │  │ Deliveries+history │   Reports: frozen windows
      └───────────────────┘  └───────────────────┘  └────────────────────┘   Org set-up: levels, units, settings
  • Why: each context can change, be tested or one day be rewritten (Forecasting in another language, for example) behind its own contract.
  • Parallel writes: a refresh and a forecast run write different rows in different aggregates, so they stop trampling on each other. On SQLite writes still queue one after another, but they get short and conflict-free. The first test is moving forecasts off the Feature, measured before and after.
  • Domain events are how one context tells another that something happened. Reads go through the owner's contract, never its tables.

Who decides which setting

Teams and Portfolios keep their freedom, but most of how they work starts from an organisation default.

Levels are pairs

"Somewhat Flight Levels": each level pairs a unit that owns the work with the unit of work assigned to it.

level             owning unit                unit of work
──────────────    ───────────────────────    ─────────────────────────────
n  strategic      Program / portfolio board  Strategic Initiative / Project
2  coordination   ART / value stream         Change / Capability
1  operational    Team  (has throughput)     Story  → rolls up to Epic
  • Levels and their names are set once per installation, like Terminology.
  • Deliveries become a property of a level above the Team, not of a Portfolio.
  • "Portfolio" is used today for a product with releases, an ART and a value stream: one word, three meanings.
