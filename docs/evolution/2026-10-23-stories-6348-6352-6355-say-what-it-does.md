# Say what it does — Stories 6348, 6352 and 6355

Delivered 2026-10-22 to 2026-10-23 in three slices of six steps, one slice per ADO Story, each shipping on its own:
#6348, #6352 and #6355. No parent Epic. Frontend only: no backend, API, migration, licence gate or setting changed.
All three come from one early adopter's feedback on large Jira Portfolios (400 to 920 Features), reported by
community member [Steve Pereira](https://www.linkedin.com/in/devopsto/).

Three settings did something the screen did not say. **Closed Items Cutoff** limited how far back metrics,
forecasts and Reports could reach, and an admin found out only when a Then & Now report refused its window.
**Dependency Field** and **Parent Override Field** read one end of a link, and nothing said which: picking *blocks*
instead of *is blocked by*, or *Issue Links*, matched nothing and silently hid the native links. The **Release
picker** greyed out every Release without a date under "No Release Date Set", which read like a broken list, and
nothing hinted that typing filters hundreds of Releases.

Each control now says what it does where it is set. Copy and hints only: nothing that is read, saved, validated or
pickable changed.

## What shipped

### Story #6348 — Closed Items Cutoff says what it limits (slice 01)

| Step | What it changed |
| --- | --- |
| 01-01 | The always-visible line under **Closed Items Cutoff (days)** on the Team and Portfolio settings now reads "Finished {Work Items} older than this many days are not kept. This limits metrics, forecasts and how far back Reports can reach. 0 keeps them all. Raising it brings older ones back with the next update.", with the Work Items term on a Team and the Features term on a Portfolio, in the tenant's own words. It is the field's accessible description. `AdvancedInputs`' `parentOverrideDefault` became required, so no caller gets Team wording by accident. |

### Story #6352 — Dependency and Parent Override say which way round they read (slice 02)

| Step | What it changed |
| --- | --- |
| 02-01 | The dashboard widgets' info button was extracted into a shared `InfoPopoverButton`. Widgets look and behave as before, and their button gained the accessible name "About {widget title}" it lacked. |
| 02-02 | `FormSelectField` takes an optional `info`; when set, an info button named "About {field label}" sits beside the select and opens a popover with the tip and a "Learn More" link (new tab, `noopener noreferrer`). |
| 02-03 | Parent Override (Team and Portfolio settings) and Dependency (Portfolio settings) carry the tip. Copy lives in one module, `fieldDirectionTips.ts`, keyed on the connection-default name: Jira *is blocked by*, not *blocks*, and *is caused by*; Azure DevOps the Reverse end, Predecessor, and a field holding the parent's id; a tracker-neutral sentence for every other tracker. Each tip says what None does, and the Dependency tip that a chosen field replaces the native links rather than adding to them. |
| 02-04 | The connection page's Parent Override (Teams and Portfolios) and Dependency defaults carry the same tips. Estimation, Size Estimate and Feature Owner carry none. |

### Story #6355 — The Release picker says why and invites searching (slice 03)

| Step | What it changed |
| --- | --- |

A Release without a date stays unpickable, and its row now reads "No date in Jira: set one there to follow it", falling back to the tenant's term for the work tracking system when the source names no tracker. "No longer available" is unchanged. |

## Decisions

### DISCUSS (2026-10-22)

- **One slice per Story, each shipping alone** (D1); **copy and hints only** (D2): no validation, no endpoint, and
  a dateless Release stays unpickable because a Delivery takes its date from it. Picking or overriding it is
  follow-up Story #6356, in Next.
- **Tracker-aware direction copy** (D7): a Jira-only example would mislead an Azure DevOps admin.
- **Configurable terms throughout** (D4), never "Epic" or "Story".

### Maintainer decisions (sketches reviewed, 2026-10-22)

- **MD-1:** #6348 rewrites the existing helper line; no info icon. "Reports", not "Then & Now report".
- **MD-2, MD-5:** #6352 gets an info icon beside the select. MD-5 replaced MD-2's hover tooltip with the dashboard
  widgets' click popover after the review gate showed a link inside a hover tooltip cannot be reached by keyboard
  nor announced by a screen reader.
- **MD-3:** #6355 shows an inline caption on the row, no tooltip, and a search placeholder. The placeholder follows
  the picker's real label, so "Type to search Jira Releases" rather than the sketched "Type to search Releases";
  recorded as an autonomous reading for the maintainer to revisit.
- **MD-4:** all three Stories tagged **Release Notes** in ADO.

### DESIGN

- **DDD-1:** extract `WidgetInfoButton` into `InfoPopoverButton` rather than extend `InfoTooltip` (`InfoTooltip`
  stays untouched).
- **DDD-2:** an optional `info` on `FormSelectField`; unset renders exactly as before (open/closed through an
  optional prop).
- **DDD-3:** `directionTip(field, tracker, terms)` keyed on the connection-default name, so an impossible pair (a
  Team Dependency tip) cannot be expressed and the per-owner docs link falls out of the key. A per-tracker strategy
  hierarchy was rejected: a lookup suffices.
- **DDD-5:** the cutoff's term is told apart through the now-required `parentOverrideDefault`, not a new prop.
- **DDD-6:** the tracker word for #6355 comes from a frontend map on the source key; a tracker name on the backend
  delivery source was rejected while Jira Release is the only source. The placeholder appends "s" to the source
  name, a known limit accepted for now.
- No ADR: no decision here outlives the copy it carries. `brief.md` unchanged: no component boundary moved.

### Deviation from DESIGN DDD-3, made in the final cross-slice refactor

DDD-3 had the connection page decide which defaults carry a tip through a `tip` flag added to their
`WhereEachDefaultSits` entries. The final refactor (`1db520c68`, `90f3b77bb`, `aab22e9b3`) dropped the flag:
`directionTip` now takes any connection-default name and returns no tip for a setting whose field reads no link, so
the copy module alone decides which defaults carry one. One place knows both the copy and where it applies, and a
new default cannot be flagged without its copy. The final review then had this pinned: no tip on Size Estimate,
Feature Owner or Estimation (`121415fed`, proven fail→pass).

## Issues encountered

- **The tip read the wrong tracker.** On a Team or Portfolio whose loaded connection differed from the tracker its
  settings carried, the tip spoke of the settings' tracker. Slice 02's review caught it; the tip now follows the
  loaded connection first (`3935ce5f1`).
- **The popover was not announced as what it is.** The extracted button opened a popover screen readers did not
  name; it is now a dialog named after its button (`03f6313eb`), for the widgets too.
- **`Object.hasOwn` is not available.** `tsconfig` targets `lib` es2021, so the "does this setting carry a tip"
  check uses `Object.keys(...).includes` (`eba92a37d`).
- **`EditConnection.defaults.test.tsx` flaked with `window is not defined`.** Pre-existing and already in the CI
  learnings ledger; not caused by this feature.

## Lessons learned

- **A link in a hover tooltip is unreachable.** The review gate's accessibility finding (MD-5) moved #6352 onto an
  existing, keyboard-reachable popover before any scenario was written; extracting it gave the widgets an
  accessible name for free.
- **Mutation on copy-and-layout changes lands below the gate honestly.** Most mutants in a UI-copy feature are
  `sx` and placement literals jsdom cannot see. Judge the per-file score with those set aside, and kill what is
  left; here that was two real gaps.
- **Let the copy module decide where copy applies.** A flag on the caller's entries (DDD-3) split one decision
  across two files; the final refactor put it back in one.

## Open items (for the maintainer)

- On Jira and Azure DevOps, the Dependency default's helper caption and its tip may now say overlapping things;
  check the two read well together.
- The Release picker's placeholder may only show once the picker has focus (MUI shows a labelled input's
  placeholder only when the label floats).
- The info icon's vertical alignment beside a select that carries a "Set on the … connection" helper line.
- The connection page shows two "About Parent Override Field" buttons (Teams and Portfolios); their names do not
  tell them apart.
- The placeholder pluralises naively (`${sourceName}s`), fine while Jira Release is the only source.
- The flaky `EditConnection.defaults.test.tsx` (`window is not defined`), pre-existing.
- K1 and K2 follow-ups after the release that carries these Stories.
- Follow-up Story #6356 (follow a Release with no date, or with its own date) is in Next.
