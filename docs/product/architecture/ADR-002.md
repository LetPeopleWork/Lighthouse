# 002 A Cycle Time outlier is above the Cycle Time UNPL\, judged by a replaceable backend outlier definition
Status: Proposed

## Context

```text
ADR-282 set Cycle Time scatterplot outliers at 5 x median in the frontend. A team saw 20+ outliers while its Cycle Time process behaviour chart flagged far fewer. The maintainer wants the outliers to match the chart, a switch to see every item, no configuration now, and a rule that can be replaced later.
```

## Decision

```text
The backend Flow metrics module judges outliers through ICycleTimeOutlierDefinition; the one implementation sets apart closed items whose Cycle Time is above the unrounded UNPL of the Cycle Time PBC (same baseline, same formula and comparison as XmRCalculator, also for named Cycle Time definitions). Without usable limits it answers NoLimits and nothing is set apart. GET cycleTime/outliers serves the verdict; the frontend partitions by its ids. Supersedes ADR-282 decisions 1 to 3 for the Cycle Time scatterplot; its decisions 4 to 7 stay.
```

## Alternatives

```text
Reuse cycleTime/pbc in the frontend: rounded UNPL disagrees at the boundary and has no named variant. Recompute XmR in TypeScript: a second owner of the rule. Frontend strategy: named Cycle Times and baseline live in the backend. Keep 5 x median: disagrees with the chart.
```

## Consequences

```text
One additive route and DTO; Program.cs gains one registration; the outlier glossary entry in ADR-270 changes; no PBC output changes; another definition is one new class and one registration.
```
